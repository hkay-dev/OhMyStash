# OhMyStash: Fix UTF-16 origin slicing, 64-bit NTFS ino check, and split blank row and 2 more

Changed: OhMyStash now rereads its settings when you resume a chat in another folder, skips a stash that a double press saved twice, drops the blank preview row in This chat, and builds against OMP 18.19.0 as release 1.17.0.
Try: not tried yet. Open the stash browser in Side by side layout on This chat and check that the preview starts right under the info row.

## What changed

- Fixed: The side-by-side preview no longer shows a blank row above the first line when browsing this chat. (ohmystash#j120)
- Fixed: Resuming a chat in another folder now picks up that folder's OhMyStash settings. (ohmystash#039z)
- Improved: OhMyStash now builds against OMP 18.19.0 and ships as release 1.17.0. (ohmystash#cta9)

## Calls

- Cut session and folder names at the existing stored limits (512 and 255 UTF-16 units) instead of a new 200 limit, never splitting an emoji, so a cut name always passes validation. (ohmystash#j120)
- The 500 ms duplicate-save skip matches on chat, input mode, text and attachments, and any restore resets it, so stashing a just-restored prompt again still saves; other saves are never skipped. (ohmystash#039z)
- Kept the peer dependency floor at ^18.14.0 since no 18.19-only API is used; only the dev pins moved to 18.19.0, and the release is 1.17.0 rather than a major bump. (ohmystash#cta9)
